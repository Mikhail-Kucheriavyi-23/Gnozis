# GNOZIS — EVOLUTION RECORD

This document separates historical development from the current state. Historical formulations are not automatically current requirements.

## Phase 1 — Ψ intuition

The project began as a search for a minimal framework capable of representing processes in terms of state, relations, information transformation and evolution. Phenomenological observations were treated as prompts for formalization rather than as evidence.

## Phase 2 — Ψ minimalization

Several formulations were explored. The lineage progressively moved toward the compact form:

```text
Ψ = (X,R)
```

The purpose of the reduction was to avoid making derived mechanisms fundamental before establishing the smallest useful state/relation substrate.

## Phase 3 — Endogenous evolution

The central question became whether evolution can be represented as an internal operator rather than as repeated external correction:

```text
X_(n+1) = E(X_n)
```

The research then extended this idea to state/rule-state formulations and local dependence.

## Phase 4 — Generate / Test / Select

A concrete computational evolutionary pattern emerged:

```text
Generate → Test → Select → Evolve
```

An important invariant was established: selection must operate only on candidates that passed the relevant test. This became an explicit software contract.

## Phase 5 — Adversarial purification

The project increasingly focused on eliminating hidden external operators: human confirmation, external selectors, global observers and hidden metadata that could secretly determine the fundamental transition.

Extensionality became an explicit test target: identical fundamental `(X,R)` projections should not produce different fundamental results merely because auxiliary hidden metadata differs.

## Phase 6 — UROBOROS / Ψ-Core

The ideas were translated into a small computational implementation: State, Relation, Engine, evolutionary transition and UROBOROS recursive wrapper. This became the basis for reproducible software experiments.

## Phase 7 — GNOSIS public baseline

On 2026-09-03 the repository published GNOSIS as a public research platform with UROBOROS / Ψ-Core v33 as the reference baseline. The public README explicitly separates implemented behavior from unvalidated research architecture.

## Phase 8 — 2026-09-08 baseline freeze

The repository recorded an evolution baseline requiring preservation of endogenous state evolution, Generate/Test/Select integrity, internal selection, reproducibility and separation between AI interfaces and the core.

## Phase 9 — Current consolidation

The project is now moving from version-driven experimentation toward a living-state architecture. The immediate objective is to maintain a single authoritative project state, preserve historical failures, and make every future experiment start from the same verified baseline.

## Historical discipline

A future change must answer:

1. What current invariant does it preserve?
2. What new evidence motivates it?
3. What old mechanism does it replace, if any?
4. Which claims change status?
5. Which tests must be rerun?
6. Does the new design actually reduce or increase fundamental complexity?

No historical version is authoritative merely because it has a larger version number.
