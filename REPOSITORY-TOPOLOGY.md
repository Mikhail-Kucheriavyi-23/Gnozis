# Gnozis Repository Topology

Repository count is not an architectural goal.

## Current connected repositories

- Gnozis — public; active product/core candidate.
- Gnozis-Genesis — private; protected implementation and future module factory.
- Gnozis-Research-Memory — public; machine-readable research/knowledge corpus.
- Gnozis-Exchange — currently empty; possible opportunity/contract boundary.
- Thoth — currently empty.
- Athena — currently empty.
- Hephaestus — currently empty.
- Daedalus — currently empty.
- Prometheus — near-empty.

## Target minimum topology

### Gnozis
Public product surface and open development. Minimal trusted runtime, public adapters, documentation, examples, and open capabilities.

### Gnozis-Genesis
Private protected system. Proprietary orchestration, private module-factory logic, sensitive evaluation/governance mechanisms, and private commercial infrastructure.

### Gnozis-Research-Memory
Machine-readable knowledge and evidence layer. Public or selectively published research can be consumed by projects without copying the whole system. Mathematics, physics, history, and other research collections belong here when publication is appropriate.

### Optional Gnozis-Exchange
Separate only when opportunities, contracts, confidential collaboration, or marketplace infrastructure require an independent security, ownership, or release boundary. Otherwise merge useful content into Gnozis.

## Unjustified repositories

Thoth, Athena, Hephaestus, Daedalus, and Prometheus currently have no demonstrated repository-level boundary. They must not become permanent repositories merely because they have names.

## Deletion rule

Never delete a repository before auditing its contents, migrating unique IP/history, mapping dependencies, verifying the destination, recording migration, and making an explicit retention decision.

## Product principle

Users should not need to understand repository topology. They connect a project and receive seamless context through explicit permissions and knowledge sources. Repository separation exists for security, ownership, release, and collaboration—not to expose internal complexity.
