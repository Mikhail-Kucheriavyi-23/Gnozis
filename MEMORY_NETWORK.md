# Gnozis Memory Network

Gnozis is designed as an open ecosystem around a protected proprietary Kernel.

## Open ecosystem

Domain repositories can provide versioned, reusable knowledge and research:

- mathematics;
- philosophy;
- physics;
- biology;
- engineering;
- computer science;
- economics;
- systems research.

Developers and researchers can clone, fork, extend and contribute to these resources using standard GitHub workflows.

## Private boundary

The proprietary Kernel remains outside the public knowledge repositories.

Open repositories provide evidence and reusable resources. They do not receive authority over Kernel state.

## How a memory source becomes usable

```
repository
  -> registered memory source
  -> provenance/schema validation
  -> Kernel evaluation
  -> verified memory
```

A repository is therefore a **memory source**, not the Kernel itself.

## Community loop

```
Gnozis Kernel
  -> research question
  -> open/domain repository
  -> community contribution
  -> new version
  -> verification
  -> Kernel may consume approved evidence
  -> new capability
  -> new public resource
```

This creates an extensible ecosystem without requiring public access to proprietary Kernel internals.

## Developer model

The public ecosystem can expose open libraries, schemas, SDKs, datasets, validation tools and domain resources. Independent repositories can be used without requiring access to the private Kernel.

## Repository rule

A new repository should be created when it provides an independent domain, lifecycle, ownership, access policy, provenance boundary or community.

Repository count is therefore a consequence of ecosystem growth, not a fixed architectural target.
