# Gnozis — Development Archive

## Role

This repository is now treated as the **temporary Development Archive / Research Memory** for the canonical Gnozis-V2 Core.

It preserves the project's accumulated research and engineering memory while the runtime Core evolves.

It is not the canonical runtime and it does not own Ψ state/evolution authority.

## What the archive contains

- historical research and reverse-analysis;
- mathematical models and hypotheses;
- experimental implementations;
- AI_CONTEXT and engineering context;
- audits and adversarial findings;
- migration records;
- development tasks and unresolved questions;
- evidence and observations that require later engineering action.

## Development loop

Gnozis-V2 runtime → observation / failure / finding → Development Archive → bounded task / hypothesis / audit → implementation proposal → verified Gnozis-V2 change → runtime observation → repeat.

## Authority

Archive storage is not authorization.

An archived proposal, task, mathematical result, or AI-generated analysis cannot directly mutate or activate Gnozis-V2.

Only verified implementation and the applicable Core transition/governance/authorization rules establish runtime capability.

## Gradual reduction of dependence

The archive is intentionally temporary as an **operational development scaffold**.

As Gnozis-V2 acquires verified native capabilities for finding generation, context reconstruction, task formation, experiment planning, self-analysis, and governed adaptation, those functions may progressively become Core-native.

The archive should then move toward a historical, research, and independent-review role rather than being a mandatory runtime dependency.

## Permanent external functions

Even at high maturity, independent audit, human oversight, historical research, and external challenge may remain outside the Core by design.

## Research status rule

Research material is not automatically implementation truth.

Use explicit status labels: DEFINITION, OBSERVED, DERIVED, VERIFIED, REJECTED, OPEN.

## Relationship

Development Archive → controlled engineering bridge → Gnozis-V2 Core → runtime interaction / learning / evolution.

The canonical runtime remains Gnozis-V2.
